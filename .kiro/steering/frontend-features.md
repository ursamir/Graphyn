# Frontend features (graphyn-ui)

Persona UX notes for feature screens. Shell/nav labels: `frontend-canvas.md`. Canonical IA: `docs/IA_PROJECT_FIRST.md`.

**Nav labels:** Workspace strip: Home · Editor · Runs · Models · Ship · Datasets. Library and admin: Templates · Agent inbox · Plugins · Workers · Credentials · Ops · Access.

**Client / polling contracts (2026-09-30):**
- `apiFetch` forwards the caller's `AbortSignal` for the whole response lifetime (headers **and** body streaming); `timeoutMs` covers the headers phase only; a caller-aborted request is never retried. `parseError` / `configuredActor` are exported from `api/client.ts`.
- Background polls use `lib/usePolling.ts` (pure loop `startPolling`; in-flight skip; the **immediate first call always runs, even in a hidden tab** — only interval ticks pause while `document.hidden`, catch-up on visible): Runs status (2 s) + Live tab (3 s), Workers (15 s), NotificationBell (45 s), App pending-proposals badge (60 s). Poll failures toast once per outage. Endpoints read by more than one component go through `lib/sharedFetch.ts` so a poll cycle issues one GET (notifications, `proposals?status=pending`).
- **Terminology:** UI says **workspace** for the project concept (API fields stay `project`). Server “Invalid project name …” / “Project 'x' not found|already exists” are rephrased by `lib/workspaceName.ts` `workspaceErrorMessage()`; client validation `workspaceNameError()` mirrors the server rule (letters, digits, `-`, `_`; 1–128).
- `graphyn-ui/nginx.conf` `/api/`: `proxy_buffering off` (NDJSON/SSE), `proxy_read_timeout 3600s`; server `client_max_body_size 2g`.

**Workspace validity (`lib/workspaceValidity.ts`):** every workspace id from the URL or resumed from localStorage is checked with `GET /projects/{id}` (200/404) before it is persisted. The store only writes `graphyn.activeProject` for validated ids (`commitActiveProject`); `noteRecentWorkspace` ignores known-missing ids. A missing URL id (any `/workspaces/<id>/…` route) renders `components/WorkspaceNotFoundView` (links: most recent valid workspace + All workspaces), title "Graphyn · Workspace not found"; the store falls back to the most recent valid recent (`pickFallbackWorkspace`), not "No workspace open". Recents not in `GET /projects` are pruned on boot (`pruneRecentWorkspaces`). While an **unknown** id is being checked the main pane shows “Opening &lt;id&gt;…” with a pulse; hops inside an already-active or recent workspace skip that blank gate (optimistic paint).

**Navigation guard (`lib/navigationGuard.ts`):** `registerNavigationGuard(fn: () => boolean | string): () => void` (false/'' = clean; true/message = unsaved). `confirmNavigation()` (window.confirm "You have unsaved changes in the Editor — leave anyway?") is consulted by sidebar/jump keys (`App.go`), header Switch / Back-to chip / Last-run menu, every command-palette item, and `routes/nav.ts` `goView` / `guardedNavigatePath` (both return false when cancelled). The Editor registers its dirty guard.

**Titles:** `Graphyn · <View>[ · <workspace>]` — workspace suffix only on workspace-scoped URLs; picker = "Workspaces"; unknown URL = "Graphyn · Not found"; `/login` = "Graphyn · Sign in".

**Path routes:** `src/routes/paths.ts`, `viewMap.ts`, `nav.ts` (`goView` / `guardedNavigatePath` / `replacePathSearch` / `onPathChange`). Views must not write `#/...`. `stripLegacyAppHash()` in `parsePath.ts` drops a leftover `#/…` fragment. `/admin/secrets` canonicalizes to `/admin/credentials`.

**Shared UX helpers (2026-10-03, UX overhaul):** `lib/metrics.ts` — `formatMetric(0.5611)` → `0.561` (`{percent:true}` → `56.1%`), `metricLabel`, `isRatioMetric`, `pickPrimaryMetric` / `primaryMetric(run)` (`summary.primary_metric` → flat `metrics` by preference test_accuracy > accuracy > val_accuracy > f1), `regressionOf`, `formatDelta`. `lib/runDisplay.ts` `runDisplayName(run)` — backend `display_name` (top level or `meta`), else humanized non-generic `graph_name`, else `Run <short id>`; never the bare "pipeline". `api/errorCode.ts` `apiErrorCode(err)` / `apiErrorDetail(err)` read `{error:{code}}` / `{detail:{code}}`. **Error text (2026-10-04):** `lib/errorText.ts` `errorMessageFromBody` turns every API error shape (`{detail}`, `{detail:{code,message}}`, `{error:{code,message}}`, `{code,message}`, `{error:"code",detail}`, pydantic lists) into one human line — `api/client.ts` `parseError` uses it (body read once as text; HTML error pages fall back to `HTTP <status>`). `humanizeErrorText` is the safety net in error toasts (`pushToast` tone `error`, or any message starting with `{`), `ErrorBanner` messages and Overview trace warnings / recent errors (`run_not_found:96505918 · no_node_stats_or_artifacts` → “Run not found (96505918) · No node stats or artifacts”). Never render a raw JSON error body. Every list consumer normalizes with `unwrapList` (bare array or `{items}`) — never `Array.isArray(x) ? x : []` on `/runs`, `/projects/*/pipelines`, `/data/*`.

**Per-view crash boundary:** `components/ViewErrorBoundary` wraps only the main pane in `App` (`resetKey=view`) — a crashing page shows “This page failed to load” with **Reload page** / **Try again** / **Report** (copies `lib/crashReport.ts` text) while the sidebar/header keep working; switching view clears it. The app-level `ErrorBoundary` remains the last resort.

**Copy rules:** primary UI copy never shows env var names, API routes, raw workspace paths or internal ids — those go in `title` tooltips or an **Advanced** disclosure. “Model stage” (staging / production of a trained model, Models page) and “Pipeline version” (published graph versions, Home) are always named that way.

## Models (`ModelsView`)

- `ViewShell` + `MasterDetail` (shared `graphyn.layout.master`); list registered models; request/approve production; register from name + training run (+ model file picker when `GET /runs/{id}/models` exists → sends `model_path`, name prefilled from `suggested_name`; 422 `compiled_untrained` → confirm then `allow_untrained:true`; `model_not_in_run` explained). Old APIs fall back to `slug`.
- Scope: `SegmentedTabs` in toolbar (**This workspace** | **All workspaces**) when a workspace is open; master rows show `modelDisplayName` (backend `display_name`, else node-id-like names such as `edge_optimizer_0` → “Edge Optimizer model”; raw name in tooltip) + headline metric; detail empty → compact `EmptyState`.
- Detail stage cards (“Model stage · staging/production/latest”, help tooltip per stage): facts from resolved registry stage fields (`features/models/modelDisplay.ts` `stageFacts`: primary metric, format, size, classes), **From run** = `source_run_display_name` / `runDisplayName`, path label + producing node (from stage or matching `GET /runs/{id}/models` row), created time, `exists:false` warning. **Request production** carries a plain-language explanation (approver must confirm). Note under the cards distinguishes model stages from pipeline versions.
- **Use in Ship** navigates `…/ship?run_id=&model=&stage=` (staging first) so Ship preselects that model.
- Detail: **How it was made** → `openTrace({ runId, step })` → `…/runs/<id>/lineage?step=<node_id>` (producing run + step from lineage `made_from`, else the stage's `run_id` / `node_id`); Runs focuses that step (see Runs `?step=`). **Datasets** / Home when workspace known.
- **Lineage (2026-10-04):** `GET /models/{name}/lineage` (`features/models/modelLineage.ts` `buildModelLineage`, tested). Each stage card gets a **Made from** block: dataset(s) `datasetLine` (label · hash · files · version), run short id, step `stepLine` (label · plugin version · code hash), seed / graph hash / model hash, environment, key step settings in a collapsed fold, “How it was made →”. **Used in** = lineage `used_in` (package runs: name, short id, stage, package sha256, actor + verified tick, status, time) + **Packages** list. 404 (older API) → previous client-side Used in (`modelUsedInRuns`).
- **Stage vocabulary:** one set everywhere — `modelStageLabel`: staging → **Staging**, prod → **Production**, latest → **Latest** (Models, Register dialog in Runs, “Mark all outputs as”, list summaries).
- **Used in** fallback (older API, workspace open): runs from the already-loaded `GET /runs?project=` rows whose meta `lineage_request.model.name` (what Ship declares) — or a row `lineage.models[]` if present — names this model, excluding the model's own source runs (`modelDisplay.ts` `modelUsedInRuns`, newest first, max 8). Record-only `lineage.models` (input-path matches) is not in list rows, so those runs are not listed.
- Responsive: `MasterDetail listLabel="models" selectedKey={selected}` + `<MasterDetailToggle />` at the top of the detail card (overlay list < 1024, list/detail stack < 768).
- Deep-link via path helpers when workspace is open. **`/workspaces/<W>/models/<name>` selects that model** once `GET /models` loads (`findModelForRoute`: exact, else case-insensitive name; back/forward via `onPathChange`), scrolls its row into view, and switches the scope to **All workspaces** when the model is not from this workspace's runs; an unknown name toasts.
- **List rows** (three lines, name never truncated): `modelDisplayName`; `modelRowSubtitle` → “run <8-char mono id> · <YYYY-MM-DD>” from the preferred stage (disambiguates same-named models; `disambiguatedModelTitles` stays exported but the list no longer suffixes titles); `modelStageSummary` → “Production 73.9% · Staging 75.6%” (no stage badges). The first visible model (or the route model) is **auto-selected** — no empty “Select a model” panel; detail shows a loading block until `GET /models/{name}` answers.
- Load error that empties the list clears `selected` / detail (no stale detail pane).

## Projects (`ProjectsView`)

- Workspaces list (`/workspaces`): list first. **New workspace** is a header button (also the empty-state CTA) that opens the inline create form (Cancel closes; closes after create). KPI tiles only with **≥ 5 workspaces**; 1–4 show one summary line (count · failed runs (click = filter activity) · last activity).
- Picker: filter + dense rows. Workspace list / filter empties and Home list panels (Activity, Continue, Always-on, linked inputs) use shared `EmptyState` (`compact` in side cards). **Create workspace** validates inline (`workspaceNameError`): message under the input, red border, Create disabled until valid; server errors rephrased via `workspaceErrorMessage`. Row ⋯ menu is Open, View runs, Clone, then Delete. The list does not use `overflow-hidden`, so that menu (including Delete on the last row) paints outside the card. Open a workspace for the typed-confirmation Delete under **Workspace**.
- **Archived** workspaces (`status === 'archived'`) are hidden from the list by default; a **Show archived (N)** checkbox next to the “N shown” count reveals them (`projects/workspaceAdmin.ts` `partitionArchived`). Only “Archived” earns a list chip (legacy draft/in-progress/ready are not shown). If every workspace is archived the list shows an “All workspaces are archived” empty state with the toggle. Rows/cards show `display_name` (`workspaceTitle`) with the id muted when it differs; search matches both.
- **Home / Overview:** first-run 2-card strip when empty (Templates · Datasets); header keeps primary **Open Editor**.
- Header: display name (id muted beside it when different; description in the tooltip) + amber **Archived** chip when archived, else the status chip (`projects/homeActivity.ts` `workspaceStatusLabel`: “Getting started” only for a draft with **no runs**; a draft with runs shows no chip) and **one summary line** “N pipelines · M runs · last run <name> <status> <time>” (`homeSummaryLine`; runs fetched with limit 30 → “30+ runs”; status via `lib/runDisplay` `runStatusLabel` → “Done”, never SUCCEEDED). Pipeline versions and datasets in use are in the line's tooltip. Until the workspace payload loads (`homeLoadedFor !== selected`) header, Activity, Continue and Always-on render skeletons — no zero / “Getting started” flash.
- **Latest result** card (`features/projects/latestResult.ts` `pickLatestResult`): newest non-failed run with a primary metric → big formatted metric, regression badge from `regression.delta` (Regression / Improved / No change vs best earlier run), **Open run** and **Open model** (registered model whose stage points at the run, from `GET /models`).
- **Datasets in use** card (was Linked inputs): choose dataset folders (`/projects/{id}/links`); pins are **bookmarks** for Datasets scoping and the Editor path picker — they do **not** rewrite pipeline ingest paths. Home picker only lists `accessible !== false` labels (same as Datasets Browse). UI manages **input** pins only (`links.outputs` is API-only). Runs don't add folders automatically. Versions & taxonomy collapsed. When there are no schedules **and** no datasets chosen, Always-on + Datasets in use collapse into one compact **Set up** row (Add a schedule → Ops · Choose datasets → reveals the card). Section titles are sentence case (`SECTION_TITLE`), not the ALL-CAPS `ide-section-title`.
- Workspaces picker stat **With recent runs** = listed workspaces that have a run in the recent `/runs` page (“of N workspaces”) — previously “Active” counted every project id on runs, so it could exceed the workspace count.
- Pipeline **pin favorites** via `localStorage` `graphyn.pinnedPipelines.{project}` (star; pinned sort first).
- Pipeline **Rollback** near promote (POST `.../pipelines/{name}/rollback` with required `version`).
- **Always-on** strip: schedules fetched with `?project=` and filtered client-side by `schedule.project === workspace`; “Last error: …” shown; else “No schedules for this workspace” + CTA to Ops.
- **Activity** run rows (Home and the cross-workspace feed) show `runDisplayName` + primary metric (`Test accuracy 56.1%`), relative time (`created_at`, full timestamp on hover) + status badge. On Home the detail comes from `homeActivity.ts` `activityDetail`: success → best metric + “best of N paths” (`summary.paths`), failure → first error line (rose), replay → “replay of <8-char id>”; each row also shows the 8-char mono run id and `StatusBadge kind="run"` (coloured only for exceptions). Consecutive identical failures (same pipeline + error) collapse into “N more failed runs with the same error” (`buildActivityItems`, click expands). Schedule rows: only this workspace's schedules; show `last_error`; click verifies the schedule's `last_run_id` exists (`checkRunExists`) — missing → toast + Ops (Schedules) instead of a dead run link. Recent-run rows open with `{ project: selected }`.
- `open(name)` failure: keep selection, clear Home payload, show ErrorBanner (no empty-home pretend-success).
- `open(name)` has a request-sequence guard (`openSeqRef`): a slower open(A) never paints A's data under B. It loads `GET /projects/{id}` (display name, description, status) and counts `GET /projects/{id}/versions` for the delete scope.
- **No “Spec & metadata” fold.** Spec/taxonomy/contract (placeholders with no UI consumer), snapshots (redundant with pipeline versions) and dataset-version Restore (copied into an unused working area) are gone from the UI; the endpoints remain for API clients. Dataset versions + stats live on Datasets → Outputs, which has **Compare versions** (only with ≥ 2 versions; `GET /projects/{p}/diff` → added/removed/changed). Never offer “Restore version”.
- **Workspace** fold (collapsed; replaces “Workspace settings”, no Use in Ship / status select / rename-by-id): **Display name** + **Description** (“What this workspace is for”) → one **Save details** (`PUT /projects/{id}` with only changed fields; the id never changes and is shown muted). **Archive / Unarchive workspace** (`PATCH …/status` `archived` ↔ `in-progress`). **Clone as…** with `CLONE_SCOPE_TEXT` (draft pipelines + settings; not runs, models, version history or dataset outputs). **Danger zone**: removed/kept lists from `deleteWorkspaceSummary` (pipelines, dataset output versions, schedules disabled · runs, artifacts, models, audit log kept) and **Delete workspace** enabled only after typing the id (and only once the Home payload loaded — while `homeLoading` the removed list is a skeleton, and the Datasets-in-use picker reads “Loading datasets…” and is disabled, so neither shows a false “0” / empty list). Home's `/runs` fetch has its own `.catch` so a runs failure no longer blanks pins, pipelines and schedules. All of these are audited server-side as `workspace.*` (category Admin).

- Catalog empty: auth / API offline / no plugins (distinct CTAs). Narrow viewport honesty banner.

- **Run stream:** exec status matches events by `node_id` only; backend `node_index` is the *execution-order* index, so the index fallback (events without `node_id`) maps through a client topological order, never the canvas array index. Terminal = `type=done` (success) or `type=error`; a stream ending without either shows “Stream disconnected — checking run status” and polls `/runs/{id}/status` to a terminal state. - **Run-start errors** (503 registry not ready, 4xx validation, …) show an inline run-start error banner with the server detail instead of a generic toast.
- **Unsaved changes** (`graphHistory.ts`): `editorSnapshot` captures only the document (node type/label/config/placement/position, edges, name, seed — never run status/selection), compared by `snapshotSignature` to the last loaded/saved **baseline**. Dirty → amber dot on **Save** (no separate Unsaved chip); `beforeunload` prompt; an app navigation guard (`registerNavigationGuard` from `lib/navigationGuard.ts`) so sidebar / palette / workspace switch / `goView` confirm before leaving; `confirmDiscard` before an in-Editor action replaces the canvas (open pipeline/env, import, external load). Loading a graph resets the baseline and history.
- **Undo / redo:** bounded history (`HISTORY_LIMIT = 50`); rapid edits of the same field coalesce into one step (`changeKey`); Ctrl/Cmd+Z undo, Shift+Ctrl/Cmd+Z or Ctrl+Y redo (`historyShortcut`, ignored while typing in a field — browser text undo wins) plus toolbar buttons.
- **Config validation** (`configValidation.ts`): JSON-schema `minimum`/`maximum`, `exclusiveMinimum`/`exclusiveMaximum` (draft-4 boolean and draft-6 numeric), `multipleOf`, `integer`, `enum`, `minLength`/`maxLength`, `pattern`. Invalid fields get a red border + `aria-invalid`; nodes show an invalid-count badge; a banner lists issues and **Run / Save are blocked** while any exist. Conditional fields: `ui.visible_if = { field = value | [values] }` and `ui.depends_on = "field"` (truthy) or `{ field = value }` hide fields (hidden fields are not validated).
- **Log dedupe** (`logDedupe.ts`): a node `node_error` followed by the pipeline-level `error` with the same core message counts/renders once (Editor log panel + Runs → Logs pretty view; raw view unchanged).
- **Skipped nodes** (`builderRunState.ts`): on a failed/cancelled run, nodes that never started show **skipped (not run)** rather than idle/failed; a started-but-unfinished node is failed (or cancelled).

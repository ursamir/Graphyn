# Wave-1 plugin venvs (YOLO / TFLM / RAG)

Heavy ML stacks stay **out of the API image**. Wave-1 Proposed pack nodes
(`yolo_*`, `tflm_*`, `vector_store_*`, `text_embed`) use `runtime = "isolated"`
and capability-shared venvs created by:

```bash
./scripts/install_wave1_plugin_venvs.sh
```

## Layout

Default root: `$GRAPHYN_PLUGIN_VENVS_DIR` or `$GRAPHYN_HOME/plugins/venvs`
(Compose: `/data/graphyn-home/plugins/venvs`).

| Capability venv | Packages (CPU by default) | Symlinked plugin slugs |
|-----------------|---------------------------|------------------------|
| `wave1-vision` | torch (CPU), ultralytics, opencv-headless | `yolo-train`, `yolo-predict`, … |
| `wave1-tinyml` | tensorflow | `tflm-quantize`, `tflm-convert`, … |
| `wave1-rag` | torch (CPU), chromadb, faiss-cpu, sentence-transformers | `vector-store-write`, `vector-store-query`, `text-embed`, … |

## Env vars

```bash
source /data/graphyn-home/plugins/venvs/wave1_env.sh   # generated by install script
# or:
export GRAPHYN_WAVE1_VENV_VISION=.../wave1-vision
export GRAPHYN_WAVE1_VENV_TINYML=.../wave1-tinyml
export GRAPHYN_WAVE1_VENV_RAG=.../wave1-rag
export GRAPHYN_WAVE1_FORCE_CPU=1   # default — do not steal FaceRecognition GPU
```

Pytest real-backend tests honor the same `GRAPHYN_WAVE1_VENV_*` variables and
**skip** when the venv / import is missing.

## Honesty

- `config.stub=true` (default) → typed minimal outputs, no heavy imports.
- `config.stub=false` → real backend; raises with install hint if deps missing.
- `mcu_flash_ota` / `mcu_ondevice_metrics` remain **needs-api** (never fake flash).

## Server-99

FaceRecognition often holds the GPU. Keep `GRAPHYN_WAVE1_TORCH=cpu` (script
default). Do **not** run `nvidia-smi -r` or kill FaceRecognition.

Install into the Compose volume:

```bash
docker exec -e GRAPHYN_WAVE1_TORCH=cpu graphyn-api \
  bash /app/scripts/install_wave1_plugin_venvs.sh
# or host-side into a bind/volume path that maps to GRAPHYN_PLUGIN_VENVS_DIR
```

Then rebuild only if PluginPackage code must land in the image:

```bash
docker compose build --no-deps graphyn-api graphyn-ui
docker compose up -d graphyn-api graphyn-ui
```

## pgvector

`vector_store_write` / `vector_store_query` support `backend=pgvector` only when:

1. Secret/env `PGVECTOR_DSN` (or `config.pg_dsn_secret`) points at a **dedicated**
   Postgres that already provides the `vector` extension, and
2. `psycopg` is installed in the Wave-1 RAG venv.

Server-99 `sentinel-sota-postgres` (`postgres:16-alpine`) does **not** ship
pgvector — do **not** flip compose or point Graphyn at that DB for vectors.
Without a DSN, the backend raises a clear **needs-api** error and the Wave-1
default remains `chromadb` / `faiss`.
